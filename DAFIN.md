# Dafin

Dafin (Romanian for the laurel tree, the leaf in its icon) is a video editor for Windows and Linux based on
[Drift](https://github.com/CutWire-Studios/Drift) by CutWire Studios (GPL-3.0). It has a layout
familiar to Filmora users, a built-in Stock Media library and Cool Edit-style volume dots.
Dafin is not affiliated with Wondershare or CutWire Studios.

| .mogrt titles | A `.mogrt` from the Titles grid (click, or drag onto the timeline; a `.mogrt` dragged from the file manager onto the timeline too) becomes a **template title**: a video clip that keeps the template, its Essential Graphics controls and your values (`Clip::mogrt`, `MogrtSource`), saved with the project. Properties › **Template** lists the controls (text, sliders, angles, checkboxes, colours, positions, scales; dropdowns and media are shown but MOGRT Converter can't set them); each change is one undo step. The picture is rendered by the free [MOGRT Converter](https://github.com/nielsfranke/MOGRT-Converter) (AGPL-3.0, a separate program Dafin runs with arguments, never through a shell; none of its code is in Dafin, and Dafin does not bundle it) into ProRes 4444 with alpha. Renders are immutable files named by a key of template hash + values + length (`<AppData>/mogrt/cache/<key>-preview|full.mov`; templates are copied to `<AppData>/mogrt/templates/<hash>.mogrt`), written under a temporary name and renamed when complete. After every edit a short pass keeps each template clip's source range equal to its render (no speed, slip or reverse), swaps in a cached render of its current state (full before preview), and otherwise queues a half-size preview (two converter runs at a time, obsolete ones cancelled) while the last good render stays on screen — so undo, redo, duplicate, trim and reopen all find or remake the right picture. Export first renders every template title at full quality (`finalizeForExport`). Saving embeds the template and the render in the project, so it opens elsewhere without re-rendering; a missing template is shown as such with **Locate template…** (matched by content hash). Renders older than 45 days are cleared at startup. Cards say how well a template renders here: the converter draws one test frame the first time (kept per converter build) → *Partly supported* with what it left out (effects, layer styles, fonts, expressions; its German warnings are translated), *Not supported* (made in Premiere Pro), *Needs MOGRT Converter*, *Can't render*. Those open a dialog offering an ordinary editable Dafin title with the template's text instead. A zip whose preview videos can't be told apart (ties, or none matching a template by name) pairs none and says so. The converter is found where its installers put it (Program Files / `%LOCALAPPDATA%\Programs\MOGRT Converter\mogrt.exe`, `~/.local/opt/mogrt-converter/`, `mogrt` on PATH) or chosen in Settings › Asset Providers › MOGRT Converter. It renders After Effects templates only, skips effects it doesn't know and doesn't recreate third-party plugins or true 3D. Titles have no sound (`--no-audio`) | `MogrtInfo.*`, `MogrtRenderer.*` (`submit`), `sessions/MogrtTitleController.*` (`EditorState.mogrt`), `core/project/sources/MogrtSource.*`, `MogrtInspector.qml`, `MogrtTitleDialog.qml`, `OnlineAssetCard.qml`, `AssetDrag.qml` (`mogrt`), `AppControllerAdjustments.cpp` (placeable `mogrt`), `AppControllerProject.cpp` (export gate), `ProjectDependencies.cpp`, `TimelineOps.cpp` (`sourceDurationForClip`), `tests/tst_mogrt.cpp` (project-file state, control parsing, converter queue against a stand-in script) |
| Title templates | A title template is one JSON file: a text style plus the clip effects it needs (sparks…) and a few **quick controls** (text, font, colours, entrance speed) that appear at the top of the title's Properties with a reset each. ## Stock Media sources

The tab is driven by a JSON catalog. On first run Drift copies the built-in one to your app data
folder (`%APPDATA%\Dafin\Dafin\free-library\catalog.json` on Windows,
`~/.local/share/Dafin/Dafin/free-library/catalog.json` on Linux) — use **Edit catalog** in the tab to open
it, then **Reload catalog**. The `_help` block at the top of the file explains the format; any JSON
search API can be added without code changes.

Pexels, Pixabay and Freesound need a free API key each. The tab shows a **Get a free key** button
and a field to paste it; keys are stored in Drift's settings, not in the catalog.

Lottie: LottieFiles' search API needs a signed-in account, so it is not browsable here. On
lottiefiles.com open a free animation and either download the **Lottie JSON** file and drag it onto
the Stickers tab, or copy its URL and paste it into the tab's link box — it is downloaded and kept in
"My Lotties". (Links that older versions saved in the catalog move to My Lotties on first start.)

## Building the Windows installer with GitHub (no local toolchain)

1. Push this branch to your fork of Drift.
2. On GitHub: **Actions** → **Build** → **Run workflow**, pick this branch, platforms = `windows`.
3. When it finishes (first run ≈ 1 h because Skia and Qt are built/cached), download the
   `Dafin-Setup-*.exe` / portable zip from the run's **Artifacts**.

Linux: same workflow with `linux` (AppImage) or `flatpak`, or build locally per `docs/BUILDING.md`.

## Publishing an update

1. On GitHub: **Actions** → **Dafin release** → **Run workflow** on `dafin-edition`, with a version
   newer than the last release (e.g. `1.0.1`) and, optionally, what's new (Markdown). That text is
   the release notes the update dialog shows, and the **What's new** pop-up after the update.
2. It builds the Windows installer and portable zip at that version and publishes release `v1.0.1`
   with both files and `SHA256SUMS`.
3. Installed copies find it at their next check (once a day unless Settings > Updates says otherwise,
   or at once with **Check for updates** there or in the gear menu) and offer to install it. Portable copies do not update; copies installed before the updater existed need the
   first release installed by hand.

The Build workflow stays an unpublished dry run; its builds report the version in `CMakeLists.txt`.
